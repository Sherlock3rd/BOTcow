## 已实现

- SQLite 事务存储：范围、完整对话正文与证据状态、显式记忆及修订、操作幂等回执、任务和线程映射。采用本机 Node 22.17.1 内置 SQLite 3.50.0，无新增 npm 原生依赖；项目 Node 范围收紧为 22.17.1–22.x。[版本对应官方文档](https://nodejs.org/download/release/v22.17.1/docs/api/sqlite.html)。该模块仍有 ExperimentalWarning，不隐藏告警。
- 范围由已准入事件中的 profile、bot、sender、chat_type、chat_id 生成。私聊、不同群不共享记忆；群未 @ 或非白名单发送者不能入库。只投影当前派发的新消息，不导入历史 inbox。
- 聊天和业务共用 ContextBundle：人格/知识哈希、scope_epoch、最近对话、已确认记忆、当前任务、来源与预算清单。长期记忆最多 8 条，附加正文软预算 6000 字符；超过 30000 字符的必要输入转为独立来源文件，由执行器分段读取，原文不裁断。
- 自然语言记住、查看、纠正、停止使用；模型只能提取本条原文，程序验证明确意图、范围与版本。落盘后才确认。同一消息重试复用原结果。纯记忆管理没有 OnIt/DONE；混合业务通过 memory-command 接口处理明确记忆子动作，再遵守原业务门禁。
- 纠正/停止使用递增 epoch，失效该范围的旧历史输入和旧线程。首版采用保守策略：该范围旧对话暂不再进入自动上下文，但其他已确认记忆仍可用。原审计账本不删除。独立、单调的 epoch fence 阻止旧数据库备份复活已停用内容。
- 业务线程按范围和任务映射；同范围明确引用优先绑定，唯一待续任务可承接明确“继续”，多个候选只澄清。人格版本变化或 epoch 变化不恢复旧线程。任务素材有独立范围交接；失败启动已产生 thread ID 时保留映射。原跨聊天共享线程不再恢复。
- 日常文本与业务 text/post/card/file/image 回复区分 sent / reply_verified，验证发送者、会话、引用与内容证据。不把 GPT 最终文字或 mark 当作 business_verified。业务回复入口 scoped-reply 在发送前检查 epoch；回读失败仅重试回读，发送结果不确定时暂停核对。
- 投影 outbox 与 SQLite 分开持久化，有幂等 ID、字节游标及事务重放。数据库故障不重发已确认投递；记忆失败给原会话真实通知并阻塞，不报零。日常不依赖历史的问答仍可继续。
- 人格变更会废弃旧预热线程；预热只装通用人格，不预装私有记忆。明显凭证字段在新历史投影中屏蔽，不导入桌面自动记忆。

## 运行与回退

- 配置 `memory.enabled/read_enabled/write_enabled/task_isolation`；自动候选提取保持关闭。读取、写入均仅面向既有准入范围。
- 数据位置：`runtime/assistant-memory.sqlite`；新投影 `conversation-projection.ndjson`；纪元护栏 `memory-epoch-*.fence`；单独回复回执 `scoped-replies/`。这些文件均在原 runtime 忽略范围。
- 回退先设 read_enabled=false、write_enabled=false，保持 task_isolation=true；不得恢复旧共享 thread_id，不删除数据库、fence 或审计账本。记忆写入关闭时“停止使用/纠正”也会明确提示未执行。
- 数据库使用 DELETE journal + synchronous FULL，短事务串行写。备份须在进程空闲并关闭连接时复制，或用 SQLite 一致性备份接口；不要复制活动事务。恢复必须同时核对最新 fence，低版本备份会被拒绝，需要人工核对恢复，不能删除 fence 绕过。
- scoped-reply 为执行器的统一投递接口；仍是应用层门禁，业务执行器具备文件/工具权限，不是操作系统沙箱。卡片设计与外部业务写入继续遵循各自技能。
- 新库首版没有自动摘要、候选提取、向量索引和跨会话共享。中文召回先用片段匹配；多条事实未被明确纠正时保留各自来源，冲突由当前回复指出，不自动按时间覆盖。
