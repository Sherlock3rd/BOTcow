# 飞书视频上传的本地路径边界与文件大小

## 基本信息

- 日期：2026-10-22
- 分类：飞书附件交付 / lark-cli
- 任务：向原消息回复 720×1280 的前三关录屏

## 问题现象

- 从 `D:\example\botCow` 运行 `--video ..\water\...` 时，lark-cli 在上传前拒绝路径，提示文件解析结果越出当前工作目录。
- 改到 `D:\example\water` 后，38,588,534 字节的 MP4 到达飞书接口但返回 `234006: The file size exceed the max value.`。

## 原因分析

- lark-cli 的本地文件参数只允许解析到当前工作目录内部，不能借助 `..` 引用兄弟项目文件。
- 当前 bot 视频上传接口的实际大小上限低于该 38.6 MB 成片；仅验证本地文件存在不能代表飞书可接受。

## 修复动作

- 在视频所在项目目录执行上传，继续显式使用 `--profile botCow --as bot`。
- 从 Movie Writer 原始 AVI 以 H.264 CRF 28、720×1280、30 FPS 重新压制为 25,100,837 字节；抽帧确认画质后用 `--video` 和 `--video-cover` 成功上传。
- 通过 bot 可见的聊天消息列表回读，确认媒体消息文件名、115 秒时长、发送者与 `reply_to`。

## 预防办法

- 上传前先确认文件的绝对路径位于命令工作目录内；不要用 `..` 跨项目引用附件。
- 长视频上传前先用 `ffprobe` 检查格式、分辨率、帧率、时长和字节数；优先准备小于 30 MB 的飞书交付版。
- 不因文字回复成功而 mark；文字和全部附件均发送并回读后，才添加 DONE 与 mark。

## 执行前检查项

- [ ] 命令工作目录包含视频和封面，路径解析不越界。
- [ ] 飞书交付版低于 30 MB，且为 H.264/YUV420P。
- [ ] `--video` 与 `--video-cover` 成对使用，身份为 botCow bot。
- [ ] 回读媒体文件名、时长、发送者与原消息引用关系。
