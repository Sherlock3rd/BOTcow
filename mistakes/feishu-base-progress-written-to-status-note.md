# Base 进展信息误写入状态备注

## 基本信息

- 日期：2026-08-14
- 分类：飞书 Base / 字段语义
- 任务：更新“帮派树新案子”的需求流程进展

## 问题现象

- 用户要求“需求流程备注一下”时，把进展文本追加到了 `状态备注`。
- 用户指出日常进展应该写记录评论；`状态备注` 一般只在创建记录或明确要求修改备注时更新。

## 原因分析

- 把自然语言“备注一下”直接映射为字段 `状态备注`，没有区分创建时描述与已有记录的过程性沟通。

## 修复动作

- 恢复原 `状态备注`。
- 将本次宣讲、资源和开发时间写入目标记录评论。
- 更新工作流规范：已有记录的日常进展默认写评论，除非用户明确指定修改 `状态备注`。

## 预防办法

- 写入前先判断是创建记录、修改字段，还是为已有记录补充过程信息。
- “同步一下/备注一下/进展如下”默认写评论；“修改状态备注为……”才写字段。
- 评论必须定位到真实 table、record 和 view，写后验证评论创建结果。

## 执行前检查项

- [ ] 已确认目标是新建记录还是已有记录。
- [ ] 用户是否明确点名 `状态备注` 字段。
- [ ] 已有记录的过程信息默认使用评论。
