# 飞书 pending 权限错误不能无限唤醒 Codex

## 基本信息

- 日期：2026-08-14
- 分类：飞书事件桥 / 失败恢复
- 任务：覆盖 Wiki 文档中上传的原生 Markdown 文件

## 问题现象

- Markdown 覆盖因 bot 应用缺少 Drive 上传权限持续失败。
- 消息按完成事务规则保留为 pending，但事件唤醒器反复处理同一 `message_id`，形成重复 Codex 调用和重复错误提示。

## 原因分析

- 队列只区分 pending / processed，没有区分可重试临时错误与需要外部状态变化的确定性权限错误。
- “失败不得 mark”被错误等同为“必须立即持续重试”。
- 唤醒器缺少失败次数、退避时间和人工阻塞状态。

## 修复动作

- 对 `app_scope_not_applied`、ACL 不足、缺少用户确认等错误记录为 blocked/quarantine。
- 阻塞消息继续保持 pending，但停止自动唤醒；只有权限状态变化、用户明确重试或管理员解除阻塞后恢复。
- 临时网络、限流和 5xx 才使用指数退避，并设置最大重试次数。

## 预防办法

- 调度前读取失败账本并检查错误指纹、尝试次数与下次允许重试时间。
- 确定性错误在外部状态未变化时不重复调用模型或写接口。
- 验收时故意制造权限错误，确认不会形成重复唤醒风暴。

## 执行前检查项

- [ ] 已分类错误是否可自动重试。
- [ ] 已记录失败次数和下一次允许重试时间。
- [ ] 需要外部处理的错误已暂停自动重试。
- [ ] 消息仍 pending，且未伪造 DONE 或 processed。
