# 飞书 pending 权限错误不能无限唤醒 Codex

## 基本信息

- 日期：2026-08-14
- 分类：飞书事件桥 / 失败恢复
- 任务：覆盖 Wiki 中上传的原生 Markdown 文件

## 问题现象

- Markdown 覆盖持续返回 `app_scope_not_applied`。
- 消息按完成事务要求保留为 pending，但事件唤醒器反复处理同一 `message_id`，造成重复模型调用和重复错误同步。

## 原因分析

- 队列只区分 pending/processed，没有区分瞬时故障与需要人工处理的永久性故障。
- 唤醒器缺少错误指纹、退避、最大次数和 blocked/quarantine 状态。

## 修复动作

- 部署 spec 增加失败分类、指数退避、错误指纹和 blocked/quarantine 规则。
- 权限、ACL、目标不存在等错误停止自动唤醒，等待外部状态变化或用户明确恢复。
- 用户选择手动处理远端写入时，明确交付本地文件并区分本地完成与远端未完成。

## 预防办法

- 自动重试只用于网络、限流和服务端暂时错误。
- 同一 `message_id + 错误指纹` 达到阈值后停止唤醒 Codex。
- 不因停止自动重试而伪造 DONE、processed 或远端写入成功。

## 执行前检查项

- [ ] 已分类错误为瞬时或人工处理。
- [ ] 权限类错误已进入 blocked/quarantine。
- [ ] 手动接管时已交付本地文件并说明远端状态。
