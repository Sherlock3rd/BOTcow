# 任务消息 mark 后任务线程未收口

## 基本信息

- 日期：2026-11-13
- 分类：飞书事件桥 / 上下文与任务线程

## 问题现象

- 已经回复、DONE、mark 的消息仍长期出现在后续 `activeTasks`。
- 需要业务执行器判断的确认问句即使最终分类为 chat，也可能在执行器预处理阶段留下 `active` 任务映射。
- 后续模型反复看到已经结束的目标，容易重复确认句或误以为旧任务仍待处理。

## 原因分析

- `taskSession` 只创建或绑定任务，没有与 `bridge-queue mark` 建立结束状态同步。
- 消息账本的 processed 状态和 SQLite 的任务线程状态各自正确写入，但缺少跨存储的生命周期收口。

## 修复动作

- 任务消息或执行器接管的消息在通过原有 DONE/回读门禁并 mark 前，将对应任务状态改为 `completed`。
- 显式引用旧消息继续处理时，重新把对应任务设为 `active`；新一轮完成后再次收口。
- 对历史上已 processed 但仍 active 的映射做一次性回填，不重发消息、不重复执行业务。

## 预防办法

- 新建任务线程测试必须覆盖 `active -> completed -> 引用续办 active -> completed` 全生命周期。
- 验收不能只检查 processed 账本，还要检查后续 ContextBundle 不再注入已结束任务。
- chat 经过业务执行器分类时，也要清理其预建的任务映射，避免污染下一轮上下文。
