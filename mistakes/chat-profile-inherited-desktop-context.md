# 日常自我介绍扩展到未收录知识

日期：2026-11-13。

## 现象

人格及基础知识接入后的合成模型测试中，自我介绍列出了知识库未收录的 FTE 经验、用户偏好、审批等内容；不能把回答路由正确等同知识范围准确。测试没有发送飞书消息。

## 排查与修复

- 本机 Codex features list 显示 memories 默认开启；仅禁用插件、MCP、shell 和项目文档，仍不能保证没有自动记忆或技能说明。
- 日常 app-server 显式关闭 memories 与 skills.include_instructions，config/read 校验生效。业务执行器也关闭自动 memories，保持按需读取规则和技能。桌面全局配置不改。
- 基础知识说明“知识库内容”只描述实际收录条目，不把模型常识、可调用工具或未读取项目当作已有知识。
- 将人格与分类职责明确分开：轻量模型识别需求后仅输出路由标记，需求回答风格由下游执行器使用。此前将人格放在分类合同之后，两次复杂分析合成测试达到18秒超时；调整后同类输入正常输出任务路由。该现象不等于证明超时只有提示词一个原因。

## 防呆

- 真实模型验证同时检查路由和自我介绍的来源，不只验证 parser 或字符串模板。
- 需要区分模型通用知识、可调用能力、已收录知识、实时数据和当前授权。
- 分类/模型异常仍移交执行器先分类，不能提前贴表情；非需求恢复路径也禁止 OnIt/DONE。
