# 任务超时提示与停止

- 业务 Codex 子进程启动后独立计时；event_wakeup.warning_ms 默认120000、timeout_ms 默认600000。达到提示阈值发一次原消息回复，达到硬超时终止本次子进程树。即使模型没有输出也生效。
- 文本入口为“停止当前任务”或“取消当前任务”，只接受完整指令；群内需要真实@，管理员身份、发送者和会话均核对。访客不能操作。监听器单独启动控制处理器，控制指令不进入聊天或业务模型队列。
- 停止请求绑定 active-task.json 中的 run_id，而不是仅绑定PID。同一控制消息持久去重，重投不能停止后续任务。跨会话不能停止；没有运行任务时如实告知。
- 先回复收到停止请求；子进程退出后才回复已停止。Windows终止本次持有的子进程树，不停止监听、聊天进程或其他项目服务。已有外部操作不会自动回滚，进程退出也不能证明远端请求已撤销。
- 超时、取消或业务执行失败记录blocked，任务状态变为blocked/cancelled；不写DONE或成功processed，不删除原消息、线程、记忆和回执。队列继续下一条，旧任务不无限重试。用户重新发送请求时先核对旧写入结果，不能盲目重做。
- 显式追问已停止任务时保留任务来源和历史，但新建模型线程，不恢复原先已失败或已取消的线程。
- 回复入口在发送前检查停止请求，阻止停止后新业务回复；已取得回执的消息仅回读。提示使用固定正文，不附带私人业务数据或原始报错，独立幂等回执并回读身份、会话、父消息与正文。发送结果不确定时不盲目重发，记录待核对。
- 前端提示依赖飞书服务可用；发送失败写本地日志，任务仍停止并隔离。暂不提供按钮或自动重试，避免额外回调订阅与不明确的重复写入。
- 本版本计时覆盖模型执行阶段，图片预取等前置操作沿用各自既有超时；不宣称覆盖进程外部服务的回滚或所有系统崩溃。
