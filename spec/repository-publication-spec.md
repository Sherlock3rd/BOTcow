# botCow 仓库发布规范

2026-11-14 用户明确要求更新部署相关规范并上传至 `https://github.com/Sherlock3rd/BOTcow`。远端是公开仓库；本次以独立发布副本提交，运行目录不切换到公开配置。

## 发布内容

上传完整运行脚本、回归测试、合成测试夹具、部署与业务规范、当前共同人格及其上游许可、技术维护文档、配置示例。README 说明安装、配置、外部依赖、启动、维护、测试和验收边界。公开版规则、知识和会话文件使用部署模板，不继承作者私有资源授权。

真实 `config/bridge.json`、业务目标、联系人别名、词库 ID、私人会话与群上下文仅在本机保存；公开仓库提供 `*.example.json`。模板默认不开启事件唤醒和自动入群，不自动填写真实用户、群、应用或文档身份。

运行数据、SQLite、日志、inbox、回执、授权二维码、设备码、token、密钥、下载附件、个人历史分析及历史原话不发布。保留本机完整历史，不为公开上传删除或改写原始事实。第三方人设保留独立许可与来源；不擅自为整个项目添加开源许可证。

## 发布验证

1. 读取目标仓库和现有分支，保留远端历史；不用强推覆盖。
2. 在独立目录组装公开版，审查本次文件清单、个人标识、内部地址、授权材料和明显凭证模式；检查忽略规则确实排除真实配置与 runtime。
3. 对公开副本运行回归测试，确保脱敏没有破坏代码。外部知识库集成默认跳过；启用 `BOTCOW_GDI_INTEGRATION=1` 才执行本机真实知识库测试。模型合成测试需要已登录 Codex，不能冒充离线单元测试。
4. 提交前检查 staged diff 与文件清单；批量本地源码使用 Git CLI 上传。推送后核对远端分支 SHA 与本地 commit 一致。
5. 本机部署、后台事件订阅、真实飞书端到端和 Git 上传分别报告。上传成功不证明新机器已获权限，也不证明自动入群已完成真实邀请验收。

## 后续同步

本机运行目录为业务真实配置，公开副本为脱敏产物。以后更新先在运行目录维护与验证，再重建公开副本并审查差异；禁止把公开模板覆盖到生产配置。公开复制的个人路径均为示例，外部 GDI 与 Meegle 组件不随仓库分发。
