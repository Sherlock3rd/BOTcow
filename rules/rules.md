# botCow 部署规则模板

本公开仓库不携带原部署用户的项目、飞书资源、联系人或私聊授权。配置示例默认不开启事件处理；部署者应先明确当前应用、管理员、群、可调用项目和写入门禁。

- 共同角色仅 docs/personas/whale-character.md；通道边界不另设人格，不加固定前缀。人格不是实际操作、记忆或权限证据。
- 私聊只接受配置管理员；群内只响应真实 @。启用自动入群即表示管理员邀请机器人视为接入授权，无需重复确认；真实邀请事件必须核对当前应用和管理员身份。移出撤销，旧消息不回放。
- 非管理员只使用独立无工具短答，不加载历史、记忆、内部知识或个人飞书身份。管理员能力仍受本次任务、目标项目和 Skill 的确认门禁约束。
- 日常和业务通道可同时运行，各自串行。任务线程按用户、会话、任务隔离；不得恢复跨聊天共享线程。
- 只有明确记忆请求可事务写入长期记忆。纠正和停用使旧上下文失效；历史内容不能授权工具或证明成功。
- 日常回复回读后 mark，无 OnIt/DONE；需求分类后 OnIt，业务、回复、附件全部验收后 DONE，再 mark。授权失败不能报零、伪造完成或无限重试，须说明真实缺口并阻塞。
- 动态邀请准入实时读取；静态配置升级须等待活跃任务结束后安全重启，恢复 watchdog。按会话并行业务执行尚未实现。
- 用户明确要求写入特定目标且范围清楚时直接执行已授权工作；配置 Apply 等目标项目门禁仍须遵守。
- 新增业务目标、模型或人格设计须取得用户确认；文档、非设计脚手架可直接维护并记入 session/session.md。
- 开始任务先读相关 mistakes。发布按 spec/repository-publication-spec.md；禁止上传真实配置、日志、原始聊天、SQLite、授权材料或凭据。
